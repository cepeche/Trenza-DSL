# ADR-022: Rule 9 — Immediate Transition Acyclicity

**Status**: Proposed (awaiting review in seq-6 of thread `eleccion-tema-piloto3`)
**Date**: 2026-05-22
**Source**: Thread `eleccion-tema-piloto3` of Trenza Mailbox v0, Pilot 3 (autonomous coordination experiment); archived in `history/coordination/archive/2026-05-22/`.
**Participants**: César Pérez-Chirinos, CL-Code (Claude Opus 4.7 via Claude Code), GE (Gemini 3.5 Flash via Antigravity).

---

## Context

The eight verification rules currently active in the Trenza compiler
(`trenza-cli/src/validator.rs`, Rules 1–8) cover completeness, determinism,
reachability, return / no-sink, role exhaustiveness, data conformance,
slot / fills integrity, and role-type consistency. None of them rejects a
specification that *parses cleanly and is reachable* but contains an
**infinite cascade of lifecycle-driven transitions** at runtime.

The pathological case: state `A` has an `[on_entry]` effect whose `.ok`
branch transitions to state `B`; state `B` has an `[on_entry]` effect
whose `.ok` branch transitions back to state `A`. The composed system
livelocks (or stack-overflows, depending on Strand 1 target) without ever
returning control to an external event. Rules 1–8 accept this; the runtime
fails.

Rule 9 closes this gap statically.

---

## Decision

A new static verification rule, **Rule 9: Immediate Transition Acyclicity**,
is added to `trenza-cli/src/validator.rs`. Its descriptive name in the
user-facing manual is **"No Spontaneous Loops"**.

The rule rejects any context whose graph of immediate (lifecycle-driven)
transitions contains a cycle.

### D1 — Formal definition of the analysis graph

For each `context` declaration, the verifier builds a directed graph
$G_{it} = (V, E)$:

- $V$ = the set of states declared in the context.
- $E$ = the set of directed edges $S_1 \rightarrow S_2$ such that:
  - State $S_1$ has an `[on_entry]` or `[on_exit]` effect that invokes
    an action $A$.
  - $A$ has at least one declared return branch (`.ok`, `.error`, or any
    other label declared in its `external:` definition) whose target is
    state $S_2$.
  - The edge is created **without** requiring any external event between
    $S_1$ and $S_2$.

For each context, the verifier runs a cycle-detection pass (Tarjan's
algorithm or equivalent DFS) over $G_{it}$. If any cycle is found, the
compilation aborts with a diagnostic identifying the states involved.

### D2 — Treatment of external actions

By default, every declared return branch of every `external:` action
contributes an edge to $G_{it}$ on the assumption that, in some runtime
execution, that branch could resolve synchronously and immediately.

**Escape valve `@nondiverging`**: an `external:` action annotated as
`@nondiverging` (or, equivalently, a specific transition annotated
`@breaks_loop`) is excluded from $G_{it}$. The annotation transfers
responsibility for cycle-breaking to the developer, who asserts that the
external is asynchronous, depends on runtime input that cannot be
constant, or otherwise cannot participate in a tight loop.

### D3 — Treatment of `when` guards

Guards (`when` clauses) are **not** evaluated by the cycle-detection pass.
For soundness, the verifier assumes every guard can evaluate to true.

**Escape valve `@may_break_at_runtime`**: a guarded transition annotated
with `@may_break_at_runtime` is excluded from $G_{it}$. The annotation is
a developer assertion that the guard reliably interrupts the cycle in
runtime; the verifier does not check this.

### D4 — Scope: intra-context only (v1)

In its first iteration, Rule 9 analyses **each context in isolation**.
Transitions or effects that cross context boundaries — for example,
`[open_overlay]`, `[close_overlay]`, or transitions between concurrent
regions via `fills` — do **not** contribute edges to the $G_{it}$ of any
context.

A cycle that crosses contexts (e.g., overlay A on-entry closes itself,
parent on-entry reopens overlay A) is **out of scope** for Rule 9 v1 and
remains the responsibility of runtime testing (Strand 2) and developer
discipline.

A future ADR may lift this restriction once the semantic complications of
overlay re-entry and concurrent-region interaction are formalised.

### D5 — Naming convention

- **Formal name** (paper, compiler diagnostics, ADR, `validator.rs`
  identifiers): **`Rule 9: Immediate Transition Acyclicity`**.
- **Descriptive name** (user manual, error messages presented to
  developers): **"No Spontaneous Loops"**.

## Examples

### Rejected by Rule 9 (cycle, no escape)

```trenza
context PingPong:
    state A:
        effects:
            [on_entry] -> transit_to_b()
        transitions:
            on transit_to_b.ok -> B

    state B:
        effects:
            [on_entry] -> transit_to_a()
        transitions:
            on transit_to_a.ok -> A
```

Diagnostic:

```
error[trenza::rule-9]: Rule 9 — Immediate Transition Acyclicity violated
  --> PingPong:
  | Cycle in immediate-transition graph: A -> B -> A
  | hint: annotate an external with @nondiverging,
  |       or a transition with @breaks_loop,
  |       to assert the cycle is broken at runtime.
```

### Accepted with escape valve

```trenza
external clock_service [authorized_for: time]:
    @nondiverging
    action tick():
        ok -> NextState

context Loop:
    state A:
        effects:
            [on_entry] -> tick()
        transitions:
            on tick.ok -> B
    state B:
        effects:
            [on_entry] -> tick()
        transitions:
            on tick.ok -> A
```

The `@nondiverging` annotation on `tick()` removes both edges from
$G_{it}$. The verifier accepts the spec; the developer carries the
responsibility for ensuring `tick()` does not loop tightly.

---

## Consequences

- **Soundness:** Rule 9 is sound in the bounded sense — it rejects every
  specification that *can* livelock through lifecycle-driven transitions
  under the conservative assumption that all externals can return
  synchronously. False positives are mitigated by the two annotation
  escape valves (D2, D3).
- **Completeness:** Rule 9 is *not* complete for runtime divergence in
  general. Cross-context cycles (D4) and infinite recursion through
  externals annotated `@nondiverging` are not detected.
- **Backward compatibility:** existing canonical specifications
  (`examples/`, `spec/reference/cronometro-psp/`) must be re-verified
  against Rule 9 before this ADR moves to *Accepted*. Specifications that
  fail must either be refactored or annotated with explicit escape valves.
- **Implementation:** the new rule lives in `trenza-cli/src/validator.rs`
  alongside Rules 1–8. The annotation parser is extended to accept
  `@nondiverging`, `@breaks_loop`, and `@may_break_at_runtime`.
- **Paper:** Rule 9 is added to Section 3 of the ONWARD! paper
  ("Verification Rules"). The ISO/IEC 25000 mapping in
  `docs/design/iso-iec-25000-mapping.md` gains a row:

  | Rule 9: Immediate Transition Acyclicity | Reliability / Maturity (ISO/IEC 25010 §4.5.1) — *by construction* | Statically rejects specifications that could livelock through lifecycle-driven transitions; a static guarantee of a property normally observed only at runtime. |

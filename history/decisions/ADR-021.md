# ADR-021: Protocol for Multi-Interface Claude Participation

**Status**: Accepted
**Date**: 2026-03-27
**Source**: Protocol gap identified during 2026-03-26 Dispatch session (CO); ratified 2026-03-27 (CL + human)
**Participants**: Lead Developer, Claude Opus 4.6 (via Dispatch), Claude Sonnet 4.6 (via Claude Code)

---

## Context

On 2026-03-26, Claude Opus 4.6 participated in the project via Dispatch/Cowork as a
conversational coordinator — directing a Claude Code session (Sonnet) without having
direct file access. This revealed a gap in AGENTS.md: the protocol assumed every agent
has full file access, and only defined two author codes (`CL`, `GE`), both of which
conflate model identity with interface role.

The gap was documented in `history/chronicle/2026-03-26/19_CL_protocolo_gap.md`
and the amendments were ratified in this session after team discussion.

---

## Decision

### 1. New author code: `CO`

`CO` designates Claude operating as **coordinator via Dispatch/Cowork** — conversational
interface, mobile-capable, no direct file access. Today this role is filled by Opus 4.6;
the code follows the role, not the specific model version.

| Code | Role | Interface | Capabilities |
|------|------|-----------|--------------|
| `CL` | Implementer | Claude Code (CLI) | Files, git, shell |
| `CO` | Coordinator (occasional) | Dispatch/Cowork | Conversational, mobile, no file access |
| `GE` | Implementer | Gemini (any) | Files, git, shell |

### 2. Attribution rule: prefix = intellectual author

The `NN_XX_` filename prefix reflects the **intellectual author** of the content, not
who physically writes the file. If Opus (CO) originates a decision and Sonnet (CL)
executes it, the file is prefixed `CO_`.

For sessions with split roles, the header clarifies both:

```markdown
**Author:** CO (Claude Opus 4.6 via Dispatch)
**Implemented by:** CL (Claude Sonnet 4.6 via Claude Code)
```

### 3. Phase 0 addendum for the coordinator pattern

When CO operates without file access, it delegates Phase 0 to the implementer (CL),
who must surface: (1) latest chronicle entry, (2) active locks, (3) pending briefings
addressed to CO, and (4) active git branch and recent log (`git log --oneline -5`).

### 4. CO is an occasional pattern, not a permanent team role

Cowork/Dispatch is not added to the project team roster as a standing collaborator.
`CO` activates when the human reaches the project via mobile/voice through Dispatch.
The frequency of use determines whether this warrants further protocol elaboration.

---

## Rejected alternatives

- **Treating CO as a permanent third agent alongside CL and GE**: adds coordination
  overhead disproportionate to actual usage frequency. Reconsidered if usage increases.
- **Retroactive rename of `17_CL_` → `17_CO_`**: would break cross-references in other
  chronicle entries and complicate git history without meaningful gain. Entry 17 carries
  a note explaining the exception.

---

## Application in the Trenza project (2026-03-04 onwards)

This protocol was implicit until 2026-03-26. Here's how it played out in practice:

### Phase 1: Initial design (March 4–12)

- **CL** (Claude Sonnet via Claude Code): Wrote the initial design documents, explored grammar, set up repo structure. Prefix: `CL_`.
- **GE** (Gemini 3.1 Pro): Reviewed design for expressiveness, provided implementation feedback. Prefix: `GE_`.
- **Human** (Lead Developer): Directed vision, made tie-breaking decisions.

**Example chronicle**:
```
2026-03-04/01-concepto-inicial.md          (human + CL)
2026-03-04/02-diseno.md                    (CL with human review)
2026-03-05/01-memo-gemini.md               (GE analysis)
2026-03-05/02-memo-claude-respuesta.md     (CL response)
```

### Phase 2: Gap resolution (March 18–20)

- **CL** (Sonnet): Coordinated gap resolution, wrote closure memos.
- **GE** (Gemini): Implemented gap solutions, tested on examples.
- **Opus** (via Claude Code, new): Formal verification and edge cases.

**Example handoff** (2026-03-18):
```
18/06-memo-opus-resolucion-gap2.md
    ↓ "Here's the gap resolution. Gemini, implement this."
→ Gemini implements in trenza-cli/
    ↓ "Implementation done. Sonnet, verify with examples."
→ Sonnet runs compiler, tests on CronometroPSP
```

### Phase 3: Infrastructure and deployment (March 20+)

- **CO** (Claude Opus via Dispatch/Cowork, occasional coordinator): Mobile-accessible coordination when Sonnet+Gemini are context-limited.
- **CL** & **GE** (as implementers): Execute against CO's decisions.

**Example** (2026-03-26, MAPSE integration):
```
26/01_CL_briefing-mapse-vision.md           (Sonnet: what MAPSE is)
   ↓
26/02_CL_mapse-strategy.md                  (Sonnet: detailed plan)
   ↓
26/03_GE_infraestructura-y-plan.md          (Gemini: infrastructure proposal)
   ↓
26/04_CL_review-ge-proposal.md              (Sonnet: review, approve)
   ↓
26/06_CL_handoff-to-gemini.md               (Sonnet: "Your turn to implement")
```

**Key pattern**: Each handoff includes a summary of the previous session's decisions, so the next agent (or human reader) can pick up without rereading all context.

---

## How the protocol prevents confusion

Without this protocol:
- Authorship is unknown: who decided this? Was it ratified?
- Attribution is lost: which LLM found this bug? Which human approved it?
- Handoffs are chaotic: an LLM starts working without knowing what the previous session did.

With this protocol:
- Filename encodes author: `01_GE_` says "Gemini wrote this."
- Cross-references are explicit: "See ADR-014 for the formal decision" links back to the language spec.
- Handoffs are structured: "Here's the context, here's what's unblocked, here's what needs work."
